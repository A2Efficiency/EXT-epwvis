# Toolkit reorganization — design

Date: 2026-10-30
Status: design approved by user; plan not yet written.

## Goal

Turn the repo from "upstream viewer plus a deck pipeline bolted on" into a
toolkit for visualizing weather data, with three clear roles:

- **references/** — code we borrowed as a starting point. Frozen, not maintained.
- **tools/** — code we build and reuse across projects.
- **projects/** — one sandbox folder per client question, holding that project's
  unique pages, config and outputs.

## Decisions (made with the user)

1. **Cut the cord with upstream.** The mdahlhausen/epwvis viewer moves into
   `references/epwvis/` and we stop merging from upstream. The `upstream` git
   remote may stay for diffing but nothing depends on it. `CLAUDE.md` Rule 1
   ("keep changes additive") is retired.
2. **Shared `weather/` library, tracked in git.** `weather_data/` and
   `weather_files/` merge into `weather/`. It is built up over time and
   committed. The `weather_files/` line in `.gitignore` is removed.
3. **First project is `2026-NEEA-eRTU`**, taken from the commit history. The
   current deck and the zone-grid appendix move into it. A later
   `2026-NEEA-LLLC` is created the same way.

## How a project uses the toolkit

- Project pages load shared code by relative path, `../../tools/lib/...`.
- CLI steps take `--project projects/<name>` and read its `project.json`
  and write to its `out/`.
- The static server stays rooted at the repo root so relative URLs work.
- Promotion rule: code stays in a project until a second project needs it, then
  it moves up into `tools/lib/`.

## Other changes

- Rewrite `CLAUDE.md`: new layout, where new code goes, the promotion rule.
  Keep the "decisions that look wrong but are not" and gotchas sections, with
  paths updated.
- `out/`: gitignore generated decks and PNGs (135 files are tracked today
  despite `CLAUDE.md` saying otherwise). Track `project.json` and sources.
- `tools/locations.json` and `locations-weather-data.json` become per-project
  data (in `project.json`) or are regenerated by `make_locations.py`.
- Remove `references/` from `.gitignore`.
- Add `tools/cli/new_project.py` to scaffold a project folder.

## Method

One commit using `git mv` so history follows files. Then fix every path:

- `<script>` and `<link>` paths in the three pages
- `ROOT`, `WEATHER_DIR`, `MANIFEST`, `DEFAULT_TEMPLATE` etc. in the Python and
  Node CLI scripts (they compute `ROOT` as the parent of `tools/`, which changes
  when scripts move to `tools/cli/`)
- the `weather_files/...` strings written into location files

## Verification

Before moving anything, run `python tools/make_deck.py "Denver-Centennial AP"`
and the zone grid, and keep the PNGs. Run both again after the move. This is a
move, so the PNGs must be identical, apart from the sub-pixel antialiasing noted
in `CLAUDE.md`. Also open `references/epwvis/index.html` and confirm the viewer
still loads standalone.

## Risks

- Merging `weather_files/` into `weather/` will add files to git. Check size and
  duplicates first (slug-named vs TMYx-named copies of the same station).
- The upstream viewer needs its own vendored copy of d3 and friends; that is
  deliberate duplication.
- `tools/node_modules` and the Playwright cache must survive the move of
  `package.json`.

## Out of scope

Changing chart code or any chart's behavior. Rewriting the deck layout.
